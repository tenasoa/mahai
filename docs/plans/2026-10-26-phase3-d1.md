# Phase 3 — Passage de Postgres à D1

Suite de `2026-10-23-migration-cloudflare.md`. Ce document fixe les choix du schéma D1 et recense
le code à réécrire, module par module.

## 1. Le schéma

### D'où il vient

Le schéma n'a jamais été tenu dans un seul fichier : il est réparti entre `migrations_manual/`,
`migrations/` et `supabase/migrations/`, appliqués à la main dans le SQL Editor de Supabase.
Le projet Supabase étant en pause, le schéma a été **reconstruit** en rejouant ces fichiers sur un
Postgres 16 local :

```bash
PG_SOCKET_DIR=/chemin/court scripts/db/rebuild-postgres-schema.sh <dossier-de-travail>
python3 scripts/db/gen-drizzle-schema.py db/reference/postgres-catalog.json db/schema.ts
pnpm db:generate      # drizzle/XXXX_*.sql
pnpm db:migrate:local # applique sur la D1 locale (.wrangler/state)
```

- Résultat : 32 tables, 11 types enum, 141 index, 96 contraintes (`db/reference/postgres-schema.sql`).
- Toutes les colonnes en camelCase citées dans le code existent dans ce schéma.
- Deux migrations sont rejouées corrigées (`scripts/db/patches/`) : leurs clés étrangères `UUID`
  visent `"User".id`, qui est en `TEXT`. Sans correction, `referralCode` manquait.
- **À vérifier dès que Supabase est réactivé** : comparer avec le vrai schéma
  (`pg_dump --schema-only`). Si un écart apparaît, régénérer le catalogue depuis la vraie base et
  relancer le générateur.

### Correspondance des types

| Postgres | D1 (Drizzle) | Côté JS |
| --- | --- | --- |
| `text`, `varchar`, `uuid` | `text` | `string` |
| enum (`Role`, `ExamenType`…) | `text` + `CHECK (… IN (…))` | union de chaînes |
| `integer`, `smallint` | `integer` | `number` |
| `boolean` | `integer` mode boolean | `boolean` |
| `double precision` | `real` | `number` |
| `timestamp`, `timestamptz` | `integer` mode `timestamp_ms` | `Date` |
| `date` | `text` (`YYYY-MM-DD`) | `string` |
| `jsonb` | `text` mode json | objet |
| `text[]` | `text` mode json | `string[]` |

- Les dates restent des `Date` côté JS quand on passe par Drizzle, comme avec `pg`. En SQL brut,
  elles valent des millisecondes : `createdAt > ?` avec `Date.now() - 30 * 86_400_000`.
- Défauts SQL conservés (`unixepoch('subsec') * 1000`, `date('now')`, JSON vides). Les UUID sont
  générés côté application (`crypto.randomUUID()`), car SQLite n'a pas de `gen_random_uuid()`.
- `updatedAt` : mis à jour par Drizzle (`$onUpdate`), plus par trigger.
- Vérifié sur la D1 locale : défauts, `CHECK` sur `balanceAr >= 0` et sur les rôles, clés
  étrangères et unicité de l'email sont bien appliqués.
- Abandonnés : l'index `Withdrawal (EXTRACT(month…), EXTRACT(year…))` (remplacé par une plage
  sur `createdAt`), les fonctions `getcyclestats` / `getmonthwithdrawals` (appelées nulle part),
  les politiques RLS et les triggers.

### Accès

`lib/d1.ts` expose `getDb()` (Drizzle sur le binding `DB`). Tant qu'un module n'est pas migré, il
garde `query()` de `lib/db.ts`. Les deux bases coexistent pendant la phase 3.

### Règles de conversion

| Postgres | D1 |
| --- | --- |
| `$1, $2` | requête Drizzle, ou `sql\`… ${valeur}\`` |
| `NOW()`, `CURRENT_DATE` | `new Date()` passé en paramètre ; `date('now')` pour une date |
| `NOW() - INTERVAL '30 days'` | `new Date(Date.now() - 30 * 86_400_000)` |
| `date_trunc`, `EXTRACT`, `to_char` | `strftime('%Y-%m', "createdAt" / 1000, 'unixepoch')`, ou regroupement en JS |
| `ILIKE` | `LIKE` sur une colonne normalisée (minuscules, sans accents) : `LIKE` de SQLite ignore la casse en ASCII seulement, donc « é » ≠ « É » |
| `x = ANY($1)` | `inArray(colonne, liste)` |
| `::int`, `::text` | à retirer, ou `CAST(… AS INTEGER)` |
| `FILTER (WHERE …)` | identique (SQLite ≥ 3.30) |
| `RETURNING`, `ON CONFLICT` | identiques |
| `gen_random_uuid()` | `crypto.randomUUID()` |
| `transaction(async c => …)` | `db.batch([...])`. Une condition (« solde suffisant ») s'écrit dans la requête : `UPDATE … SET "balanceAr" = "balanceAr" - ? WHERE id = ? AND "balanceAr" >= ?`, et les écritures suivantes du lot dépendent de `changes() = 1` (`INSERT … SELECT … WHERE changes() = 1`) |

Aucun `FOR UPDATE` dans le code : pas de verrou de ligne à remplacer.
